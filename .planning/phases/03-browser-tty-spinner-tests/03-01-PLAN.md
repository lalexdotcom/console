**SPIN-01 describe block** — Tests that the lifecycle transitions (start/update/success/fail/stop) emit the correct output per state. Use `rs.useFakeTimers()` in `beforeAll` and `rs.useRealTimers()` in `afterAll` (D-01). Capture output using a manual stdout intercept pattern (same try/finally as captureAll) for tests that need to advance timers while capturing — since `captureAll` is synchronous and `rs.advanceTimersByTime` fires setTimeout callbacks synchronously, they can run inside the same manual intercept block.

Key tests:
1. `'start emits an immediate running frame'` — wrap `L.scope('spin-01-a').info.spin('loading')` in `captureAll`. The initial `render('running')` fires synchronously inside `start()`. Assert `stdout.length >= 1` and `stdout[0]` contains `'⋯'`.
2. `'tick advance emits additional running frames'` — capture stdout manually (try/finally around `process.stdout.write`), call `L.scope('spin-01-b').info.spin('loading')` then `rs.advanceTimersByTime(TICK_ADVANCE)`. Assert `out.length >= 2`.
3. `'update changes the spinner text on the next tick'` — use manual stdout intercept, create spinner, call `sp.update('updated')`, advance by `TICK_ADVANCE`. Assert `out.some(l => l.includes('updated'))`.
4. `'success emits ✔ icon line'` — use `captureAll(() => { const sp = L.scope('spin-01-d').info.spin('x'); sp.success('done'); })`. Assert `stdout.some(l => l.includes('✔'))`.
5. `'fail emits ✖ icon line'` — same pattern, assert `stdout.some(l => l.includes('✖'))`.
6. `'stop() terminates the spinner without emitting output'` — create spinner, then `captureAll(() => sp.stop())`. Assert `stdout` is empty (stop() does not render).

The manual stdout intercept pattern for timer-advancing tests:
```typescript

  // ... spinner creation + timer advance

  process.stdout.write = orig;
```
