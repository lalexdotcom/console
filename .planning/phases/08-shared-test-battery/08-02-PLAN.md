    **CORE-01 adaptation (critical — stdout/stderr routing tests):**
    The original tests use `captureAll()` returning `{ stdout, stderr }` and check:
      - `expect(stderr).toHaveLength(1)` / `expect(stdout).toHaveLength(0)` for stderr-bound levels
      - `expect(stdout).toHaveLength(1)` / `expect(stderr).toHaveLength(0)` for stdout-bound levels

    In the adapter model, `capture()` returns a FLAT `string[]` (all output combined). Replace routing assertions with flat-array assertions:
    - `expect(stderr).toHaveLength(1)` → `expect(lines).toHaveLength(1)` (one line emitted)
    - `expect(stdout).toHaveLength(0)` → REMOVE this line (cannot distinguish in flat array)
    - `expect(stdout).toHaveLength(1)` → `expect(lines).toHaveLength(1)`
    - `expect(stderr).toHaveLength(0)` → REMOVE this line

    The test body becomes:
    ```ts
    test.each([
      ['emerg'], ['alert'], ['crit'], ['error'], ['warn'],
      ['notice'], ['success'], ['info'], ['verb'], ['debug'], ['wth'],
    ] as const)('%s emits exactly one line', async (level) => {
      const lines = await adapter.capture(() => {
        (L as unknown as Record<string, (...a: unknown[]) => void>)[level]('msg');
      });
      expect(lines).toHaveLength(1);
    });
    ```

    Note: `L.format = 'json'` is set by `adapter.setup()` calling `L.format = 'json'` for the json/logfmt/pretty adapters. Inside the suite, do NOT override L.format — trust the adapter's setup(). Exception: for tests that explicitly need a specific format (none in levels.test.ts), set inline.

    **CORE-02 adaptation:**

    ```ts
      }
    });
    ```
