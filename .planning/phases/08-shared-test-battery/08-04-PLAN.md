    **Capture adaptation for spinners:**
    The original `spinner-node.test.ts` uses TWO capture mechanisms:
    1. `captureAll(() => { ... })` — for synchronous tests (SPIN-01 start, success, fail; SPIN-02/03)
    2. `interceptStdout(() => { ... })` — local helper for timer tests (SPIN-01 tick/update, SPIN-03 autoStart=false, etc.)

    In the suite, use `adapter.capture(fn)` for BOTH. The adapter's `capture()` implementation is async and handles both sync and async fn. Replace:
    - `captureAll(() => fn())` → `await adapter.capture(() => fn())`
    - `interceptStdout(() => { rs.useFakeTimers(); ...; rs.advanceTimersByTime(...); })` 
      → the fn passed to `adapter.capture()` can be sync and contain the fake timer logic:
    ```ts
    const lines = await adapter.capture(() => {
      rs.useFakeTimers();
      L.scope('spin-01-tick').info.spin('loading');
      rs.advanceTimersByTime(TICK_ADVANCE);
    });
    ```

    IMPORTANT: `rs.useFakeTimers()` must be called INSIDE `adapter.capture(fn)` (inside the fn itself), NOT before it. The capture wrapper patches stdout/stderr (or console spies) BEFORE fn runs, so fake timers firing inside fn will be captured correctly.

    **After timer-based tests, restore real timers:**
    Add `rs.useRealTimers()` at the end of any test that calls `rs.useFakeTimers()`:
    ```ts
    test('tick advance emits additional running frames', async () => {
      const lines = await adapter.capture(() => {
        rs.useFakeTimers();
        L.scope('spin-01-tick').info.spin('loading');
        rs.advanceTimersByTime(TICK_ADVANCE);
      });
      rs.useRealTimers();
      expect(lines.length).toBeGreaterThanOrEqual(2);
    });
    ```
